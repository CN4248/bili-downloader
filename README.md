# BiliDL · B站视频 / 动态 / 专栏图文下载器

一套 **四个形态、同一套下载引擎** 的 B站下载工具：

| 形态 | 文件 | 适用场景 |
| --- | --- | --- |
| 🖥️ Windows 桌面版 | `dist/win/BiliDL.exe`（配 `ffmpeg.exe`） | Windows 双击即用，自动开浏览器当 WebUI |
| 📱 Android App | `dist/BiliDL.apk` | 手机上独立运行（内置引擎 + 本地 WebUI） |
| 🐳 Docker 服务 | `docker-compose.yml`（端口 **2196**，`network_mode: bridge`） | NAS / 服务器 7×24 挂机下载 |
| 🐵 油猴脚本 | `tampermonkey/bilidl-pusher.user.js` | 在 B站页面上一键解析 / 下载 / 检索 UP 主 |

界面是同一个 **WebUI**（纯标准库 HTTP 服务 + 原生 JS，无框架、无 CDN 依赖）。

---

## 1. 功能清单

- **链接下载**：视频（`/video/BVxxx`、`av`号）、动态（`t.bilibili.com/xxx`）、专栏（`/read/cvxxx`）、图文（`/opus/xxx`）、UP 主空间（`space.bilibili.com/<uid>/upload/...`）；
  **自动识别 `b23.tv` 短链**（跟随 302 拿到真实链接再分类）；
  **一次可粘贴任意多条链接**，一行一条，批量解析、批量勾选、批量下载。
- **清晰度可选**：8K / 杜比视界 / HDR / 4K / 1080P60 / 1080P+ / 1080P / 720P60 / 720P / 480P / 360P，**默认 1080P60**。
  - DASH 流（`fnval=4048`）按清晰度挑选，音视频分别下载后用 ffmpeg 无损合并；
  - 拿不到目标清晰度（如未登录）时，自动退回该账号能拿到的最高 progressive（mp4 直链）。
- **下载目录可自定义**，**视频与图文分别独立设置**：
  - 默认：视频 = 根目录，图文 = 根目录/图文；
  - Docker：根目录 = `/download` → 宿主机 `/mnt/media/video`。
- **登录两种方式**：
  - B站 App **扫码授权登录**（二维码由 `passport.bilibili.com` 生成，轮询状态，成功后 Cookie 自动持久化）；
  - **手动粘贴 Cookie**（`SESSDATA=...; bili_jct=...`，也支持浏览器插件导出的 JSON）。
  - Cookie 只写入本机 `data/cookie.txt`（权限 600），不会上传到任何第三方。
- **分集（P）与合集（ugc_season）自由勾选**：
  - 分集**默认全选**（即链接对应视频内的所有分集）；
  - 合集里其它视频**默认不勾选**，可点「全选合集 / 清空合集」，也可单独点某一集；
  - 合集里每一集都是**独立视频**：下载时 `<video_title>` 取该集自己的标题（不是入口视频的标题），
    合集标题 / 序号仍由 `<videolist_title>`、`<videolist_order>` 提供；
  - 因此支持「合集里某个视频的某个分集」这种粒度。
- **重命名规则完全自定义，视频与图文各自独立**（变量点一下就插入到光标处）：
  - 视频默认：`<video_title>-<video_id>-<video_episode>.<ext>`
  - 图文默认：`<opus_title>-<opus_id>-<opus_order>.<ext>`
  - **只有模板里写的 `/` 才是子文件夹**；标题等变量值里的 `/` 自动变成 `_`
    （例：标题「【官方广播剧/中文字幕】…」→ 文件名 `【官方广播剧_中文字幕】…`，不会多建一层目录）
- **UP 主批量下载**：输入 UID 或空间链接 → 检索**全部视频**与**全部图文** → 检索完成后**分两个独立面板**展示（视频网格 / 图文网格），自行勾选再批量下载；**支持按标题搜索/筛选**（多个关键词空格分隔、需全部命中，`全选匹配` 一键选中所有命中作品再批量下载，筛选只作用于已检索结果、不会再请求 B站）；
  检索按「扫描间隔」逐页请求，下载按「单任务间隔」串行排队，**全程带随机化延迟**。
- **定时追更（订阅 UP 主 / 收藏夹 / 番剧 / 稍后再看 / 合集 / 文集）**：给每个来源建一条订阅，**各自独立**设置下载目录、扫描间隔、是否追视频 / 追图文；
  可以指定「从哪部作品开始算」，从那一部（含它本身）开始往后下载；合集订阅会连每个视频的全部分P一起下；文集订阅会盯着新增的图文并自动下载图片；
  订阅列表可按类型筛选、勾选多张批量开启 / 关闭 / 删除；每个订阅可单独开关，整体还有一个总开关；
  后台按「到点才扫、同一时刻只扫一个、两次扫描之间强制空档 + 随机抖动」的方式自动检索并下载，**不会触发风控**。
- **防风控**：见第 6 节，整个使用过程（含检索、下载、断点续传、定时追更）都控制在低频、可退避的范围内。

### 3.1 Windows：便携版（解压即用，内置 Python 运行时）

1. 解压 `BiliDL-2.2.11-win64.zip` 到任意目录（**不要**只解压某个子文件夹，`python\`、`app\`、`data\` 必须在一起）。
2. 双击 **`start-BiliDL.bat`** → 黑窗口先打印 `BiliDL 2.2.11 (Python 3.11.9)` → 浏览器自动打开 `http://127.0.0.1:2196`。
3. 换端口 / 不自动开浏览器：

```bat
cd /d 解压目录\app
..\python\python.exe -m bilidl --port 2200 --no-open
```

**怎么确认自己跑的是新版**：网页左下角显示 **v2.2.11**；或浏览器打开 `http://127.0.0.1:2196/api/health` 看 `version` 字段。

> 配置（`settings.json`、`cookie.txt`、`subs.json`）在 `data\`，下载文件默认在 `downloads\`（可在「下载设置」改），删掉 `data\` 即恢复出厂。
> 早期版本打包时把 `bilidl\` 放错层级（zip 里是 `app\bilidl\` 但内容是旧代码），会导致「解压了还是老版本」。2.2.1 起已修正并更换版本号命名。

### 3.2 Docker：`docker-compose.yml`（端口 2196 / bridge）

```bash
cd /path/to/bili-downloader
sudo ./deploy.sh                 # 一键：体检 → 构建 → 启动 → 等健康检查 → 打印地址
```

`deploy.sh` 会自己找下载目录、写 `.env`、处理 BuildKit 兼容、构建完等健康检查通过才返回；
想手动来也行：

```bash
cp .env.example .env             # 改这里的 BILIDL_HOST_DOWNLOAD（宿主机真实下载目录）
docker compose up -d --build     # 首次构建；之后改代码再 build 只重跑最后几层
docker compose logs -f bilidl    # 看日志
```

`deploy.sh` 的其他用法：`--check`（只体检）、`--download-dir /volume1/xxx`（换下载目录）、
`--test`（部署后跑一次解析自测）、`--logs`、`--down`。

- 端口 **2196**（`.env` 里 `BILIDL_PORT` 可改外层端口），`network_mode: bridge`；
- 宿主机下载目录：`.env` 的 `BILIDL_HOST_DOWNLOAD`（默认 `/mnt/media/video`）→ 容器 `/download`；
- 配置与 Cookie：`./data:/app/data`；
- 群晖 / NAS 上逐步部署（含 Container Manager 图形界面、权限、BuildKit、常见报错）见
  **[docs/DEPLOY-SYNOLOGY.md](docs/DEPLOY-SYNOLOGY.md)**；
- 构建已做「快」的优化：`python:3.12-slim` + 只装 ffmpeg（`--no-install-recommends`）+ 仅 2 个纯 Python 依赖（httpx、qrcode）+ apt/pip BuildKit 缓存挂载 + 默认国内镜像源（TUNA）+ `.dockerignore` 把构建上下文从 216 MB 压到 **1.5 MB**（排除 `.venv` 与 `dist`）。
  实测：pip 层 2.5 秒装完；宿主网络下 apt 换源后 3+ MB/s。
- 老版本 docker（BuildKit 被关）报 `the --mount option requires BuildKit` 时，改用 `docker/Dockerfile.plain`（去掉缓存挂载的等价版本）。
- 想换回官方源：

```bash
docker compose build --build-arg DEBIAN_MIRROR=deb.debian.org --build-arg PIP_INDEX=https://pypi.org/simple
```

- 打开 `http://<宿主机IP>:2196`；手机同网段可直接用 App 连。

### 3.3 Android：`BiliDL.apk`（独立运行，不需要电脑）

从 2.0.0 起 APK 是**完整的离线版**：B站 下载引擎、任务队列、WebUI 全打包在 APK 里，手机上单独就能下，不需要电脑/NAS 上的服务。

1. 安装 `dist/BiliDL.apk`（自签名，需要允许「安装未知来源应用」；minSdk 26 / targetSdk 34）。
2. 首次启动会申请「所有文件访问权限」——用来把文件存到 `Download/BiliDL/视频` 与 `Download/BiliDL/图文`；拒绝则落到 `Android/data/com.bilidl.mobile/files/BiliDL`。
3. 打开后就是本地页面（App 内置服务 `127.0.0.1:2196`）：粘贴链接 / UP 主 UID / Cookie 或扫码登录 / 设置重命名规则 / 定时追更。
4. 限制：手机里没有 ffmpeg，**只下 B站 的单文件 MP4**（登录后最高 1080P）；1080P60/4K/HDR 需要 DASH 合并，会提示换低清晰度。
5. 其它 App 里「分享」文本到 BiliDL，可带链接进来（`ACTION_SEND`）。
6. 自己构建：`bash android-app/build_apk.sh`（纯命令行 `aapt2/javac/d8/apksigner`，不用 Gradle）。

### 3.4 油猴脚本：`tampermonkey/bilidl-pusher.user.js`

1. 安装 Tampermonkey，新建脚本粘贴本文件内容（或直接拖入）。
2. 首次点右下角粉色浮标 → 填服务地址（默认 `http://127.0.0.1:2196`）→ 保存。
3. 在 B站任意视频 / 图文 / 专栏 / 动态 / UP 主空间页面，浮标会识别当前页：
   - **在 WebUI 中选择**：打开 `http://.../?links=<当前链接>`，由你手动勾分集/合集；
   - **立即下载**：直接 `POST /api/download`（视频只下当前视频的默认分集，图文下整个作品）；
   - **检索此 UP 主**：打开 `?scan=<mid>` 自动开始检索空间全部作品；
   - **多选图文**：见下一节。
4. 支持 `b23.tv` 短链页面（脚本会先跟随跳转识别真实类型）。

#### 3.4.1 在 UP 主空间页点缩略图多选作品下载（v1.3.0 起；v1.7.2 起勾选框只挂缩略图左上角、一作品一个）

在 `https://space.bilibili.com/<uid>/upload/opus`（图文）或 `/upload/video`（视频）这类**用户空间页**，
直接把页面上的作品**点一下选中**，再点底部「发送下载」即可：

1. 打开空间页，脚本会给**每个作品的缩略图左上角**加**一个**勾选框（挂在封面容器里，
   不会压到标题，也不会出现两个框），并在页面上方提示「点卡片/缩略图即可多选」；
2. **点缩略图、标题、整张卡片任意位置**都能选中（选中卡片会加粉色描边 + 打勾），
   选择模式下点击**不会跳转**到作品详情页；再点一次取消；
3. 底部悬浮条实时显示 `已选 N 个（视频 a / 图文 b）`，旁边有 `全选本页`、`清空`、`发送下载（N）`；
4. 视频和图文可以混选，发送时自动分成 `video_idents` 和 `opus` 两组提交给 BiliDL。
   想正常浏览时点一下 `选择模式：开/关` 切回关闭，点击就恢复成正常跳转。

另有「多选面板」（点右下浮标 → 「多选图文」，或手填 UP 主 ID；面板顶部有 **按标题搜索** 输入框，输入关键词即时过滤，`全选` 只作用于当前匹配结果）：
调 `POST /api/space/scan` 让 BiliDL 检索该 UP 主**全部**作品（服务端自带 1.6s/页 随机延迟，不碰风控），
封面网格里点选后统一提交，适合想翻很久以前的作品。

说明：
- 面板里的检索是**服务端**去 B站拉列表（用 BiliDL 自己的 Cookie 和节流参数 `scan_interval`），
  浏览器端不会额外请求 B站，所以不会因为脚本在页面上乱翻页而触发风控。
- 翻页延迟、并发都在 WebUI「下载设置」里可调（默认扫描 1.6s/页、并发 2）。
- 未登录也能量列表和下载（720P 以内）；登录后清晰度/稳定性更好。

### 3.5 定时追更（订阅 UP 主 / 收藏夹 / 番剧 / 稍后再看 / 合集 / 文集 · 与 bili-sync-up 对齐）

WebUI 侧栏「🕒 定时追更」。exe / Docker / APK 用的是同一套服务端，所以 Windows、NAS、手机 App 上都有这一页。

**能做什么**

- 给任意多个 UP 主 / 收藏夹 / 番剧 / 稍后再看 / **合集** / **文集**各建一条**订阅**；
- **合集订阅**：直接粘合集链接（`https://space.bilibili.com/<UID>/lists/<合集ID>`），
  合集里每个视频的**全部分P**都会一起下载；不设起点时从合集最旧的一部开始、按合集顺序补全，之后自动追新加的；
  合集列表按 100 个/页翻页，694 个的合集每次扫描约 7 个请求；合集很大时建议把这条订阅的扫描间隔调大；
- **文集订阅**：粘文集链接（`https://www.bilibili.com/read/readlist/rl1099181`）即可，添加时自动解析文集标题；
  首次扫描只建基线（现有文章不下载），之后文集里**新增的图文**会自动下载图片，落盘沿用「文集重命名规则」
  （`<readlist_title>/<readlist_order>-<opus_title>/<opus_id>-<opus_order>.<ext>`）；想补已有文章，用「链接下载」解析这个文集勾选即可；
- 每条订阅**独立**设置：视频下载目录、图文下载目录、扫描间隔（分钟）、是否追视频 / 是否追图文、**单独开关**；
- 每条订阅还可以**单独设置视频 / 图文的重命名规则**（留空=跟随全局），变量与「下载设置」里完全一致，
  视频用 `<video_*>`、图文用 `<opus_*>`，文集订阅额外支持 `<readlist_*>`；点变量即可插入模板；
- **下载目录随时可改**：保存时如果目录变了，会把旧目录里的全部文件和文件夹自动搬到新目录（同名文件加 `-1`，绝不覆盖）；
  新旧目录互相包含会被拒绝；旧目录如果是**全局下载根目录**则只改订阅路径、不自动搬（避免把整个下载库搬走）；
- 指定**起点作品**：点「视频起点 / 图文起点」，从该 UP 主的作品列表里点一部，**从这一部开始（含它本身）**往新的方向自动下载，更早的作品不下；
  候选取的是「起点 → 现在」这一段并按时间**正序**排队，所以起点作品会最先建任务（单轮 `max_new` 上限内），不会因为作品多而被跳过；
  不设起点时，第一次扫描**只建立基线**（现有作品一个都不下），之后只下新发的；
- 顶部**总开关**：关掉后所有订阅都不再自动扫描（但手动「立即检查」仍可用）；
- 每条订阅有「立即检查」，随时手动跑一次；
- 订阅列表顶部可以**按类型筛选**（全部 / UP 主 / 收藏夹 / 番剧 / 稍后再看 / 合集 / 文集）；
- 每张卡左侧有「选择」勾选框：勾多张后可以**批量开启 / 批量关闭 / 批量删除**（删除只删订阅，已下载文件不动）。

**防风控怎么做的**

| 手段 | 默认值 |
| --- | --- |
| 默认扫描间隔 | 30 分钟（最小 2 分钟） |
| 两次扫描最小空档 | 90 秒（手动「立即检查」也算一次，会自动顺延） |
| 单轮最多下载 | 20 个新作品（剩下的下一轮继续） |
| 扫描并发 | 永远串行：同一时刻只扫一个订阅，视频与图文之间也隔 2~3 秒 |
| 翻页延迟 | 复用「下载设置」里的扫描间隔（默认 1.6s/页）+ 随机抖动 |
| 抖动 | 每次真正开始扫描前随机等 1~4 秒，不出现整点规律 |
| 风控让路 | 下载侧一旦进入风控冷却，订阅扫描立刻暂停；扫描本身命中风控也会暂停 120 秒 |

**操作步骤**

1. 填 UID → 勾「追视频 / 追图文」→（可选）填两个下载目录与单独间隔 → 「添加订阅」；
2. 在卡片上点「视频起点 / 图文起点」→ 等它检索完 → 点你想当起点的那部作品；
3. 确认卡片上的「启用」勾上、顶部「开启定时扫描」勾上，就不再需要管了。

订阅数据存在 `data/subs.json`（权限 600），Docker 里对应容器的 `/app/data/subs.json`，重建容器不会丢（如果挂了 data 卷）。

### 3.4.0.1 评论区图片下载（两个油猴版本都支持）

### 3.4.0.6 独立版下载链路（v1.2.14 起，请务必升级）

v1.2.10–1.2.13 期间独立版下载可能整体失败或仍开新标签页，原因与对策：

| 问题 | 处理 |
|---|---|
| `GM_xmlhttpRequest` 用了 `responseType: "blob"`，部分 TM 版本不支持 | 改 `arraybuffer`，内部再转 Blob |
| 请求里手动带 `Origin` / `Referer`（浏览器受限头）导致请求失败 | 不再设置 |
| `@connect *.hdslb.com` 通配写法不被识别，跨域被拦 | 改 `@connect hdslb.com` / `bilivideo.com` / `bilibili.com` / `biliapi.net` + `@connect *` |
| blob 失败后回落 `GM_download`，TM「浏览器下载模式」把它变成新标签页 | 图片只走 blob（失败即报错），视频才用原生下载 |

排障：Console 里执行 `__bilidlDlLog`，看每次下载是 `blob` 还是 `blob-fail`；失败条目会带 `err`。

### 3.4.0.4 独立版下载不会新开标签页（v1.2.8 起）

独立版以前在 `GM_download` 不可用时，会用 `a[download]` 直接指向 B站 CDN 的原图地址 —— 跨域链接的 `download` 属性会被浏览器忽略，于是变成「打开图片新标签页」。现在改成：

1. **图片 / 封面 / 字幕 / 弹幕 / NFO 一律先抓成 blob**，再用同源 `blob:` 链接 + `a[download]` 保存 —— 不跨域、不跳转；
2. **视频**才用原生 `GM_download`（避免大文件进内存），失败再退回 blob；
3. 全程不使用 `target="_blank"`；
4. 每次下载都会记进 `__bilidlDlLog`（`how: "blob" | "native"`），排查时在 Console 里 `__bilidlDlLog` 一看便知。

> 注意：Tampermonkey 设置里的「下载模式」若是「浏览器」，`GM_download` 本身就可能变成打开新标签页；v1.2.9 起图片不再依赖它。

### 3.7 只下纯音频 / 无声视频 / 字幕 / 弹幕 / 封面 / NFO（可多选）

「下载设置」页新增一块「下载哪些文件」，六种都能单独勾，也可以多选：

| 选项 | 产出文件 | 说明 |
|---|---|---|
| 只下载纯音频（m4a） | `<视频规则名>.m4a` | 取 DASH 音轨重封装成标准 m4a（major_brand `M4A`）；需要登录才有高码率 |
| 只下载纯音频（mp3） | `<视频规则名>.mp3` | 转码 192k / 44.1kHz / 带标题歌手标签；老电视、车机、没有 AAC 解码的媒体库选这个 |
| 只下载无声视频 | `<视频规则名>-mute.mp4` | 取 DASH 视频轨，不含音轨；加 `-mute` 是为了不和有声版互相覆盖 |
| 额外下载字幕 SRT | `<视频规则名>.srt`（多语言时 `<名>-<语言>.srt`） | 走 `/x/player/v2` 的字幕列表；多数视频要登录才拿得到 |
| 额外下载弹幕 SRT | `<视频规则名>-danmaku.srt` | 把 `comment.bilibili.com/<cid>.xml` 的弹幕转成 SRT（每条 4 秒） |
| 额外下载封面图片 | `<视频规则名>.jpg` | 原始封面（archive 图） |
| 额外下载 NFO | `<视频规则名>.nfo` | Kodi/Jellyfin 可读的 `<movie>` XML，含标题、BV号、UP主、发布日期、简介、封面地址 |

要点：

- **默认全都不勾**，就是普通的有声视频；纯音频与无声视频**可以同时勾选**，各下一份文件（v2.1.1 起）。
- 纯音频会**优先选 AAC 音轨**（会员视频常见「AAC + 杜比 ec-3」两条，按码率选会选到杜比，很多播放器解不出 → 没声音）；
  下载完还会用 ffmpeg 把 B站 的分片 MP4 音轨**重封装成标准 m4a**（不转码），避免电视 / 媒体库认不出音轨。
  重封装失败时保留原始文件并写一条 WARN。
- **放出来没声音怎么办**：把「纯音频格式」从 `m4a` 换成 `mp3` 再下。m4a 里是 AAC，老电视 / 车机 / 部分媒体库
  没有 AAC 解码器时会「有进度条、没声音」；mp3 是转码 192k，几乎什么都能放。转码失败会自动退回 m4a 并写 WARN。
- 格式存在设置项 `audio_format`（`m4a` / `mp3`，默认 `m4a`），只影响「纯音频」这一种产出，视频/无声视频不受影响。
- 所有附加文件（字幕/弹幕/封面/NFO）都跟视频一起下载，**文件名完全沿用「视频重命名规则」**，只把扩展名换成 srt/jpg/nfo/m4a；规则里的 `/` 子文件夹照样生效。
- 弹幕 SRT 与字幕 SRT 都会自动去重、按时间排序，直接拖进播放器就能看到。
- 独立版油猴脚本自己下载时也支持这六项（设置小窗里同一组勾选框）；主油猴脚本把任务推给服务端，因此自动继承服务端的这份设置。
- 手机独立版（APK）这组选项在下一版加入。

### 3.4.0.8 独立版 v1.2.17：为什么不再弹新标签页 / 子目录怎么开

1. **不再开新标签页**：根因是保存锚点被挂进了 `document`，B站 在 document 上挂了捕获阶段的点击监听，一看是 `<a>` 就按「打开图片」处理。现在锚点不进文档、直接 `click()`，事件不会经过页面监听。
2. **图文规则里的 `/` 建子目录**：浏览器给 `a[download]` 的只有「文件名」，`/` 会被自动换成 `_` —— 这是浏览器限制。要真正建目录，打开设置里的 **「用 GM_download 保存小文件」**（默认关），走 Tampermonkey 的下载接口（downloads API 支持相对路径）。开了之后如果个别环境会弹标签页，把开关关掉即可。
3. 服务端（EXE / Docker / APK / WebUI）不受这个限制，子目录一直是真实创建的。

### 3.4.0.9 独立版 v1.2.18：新标签页彻底根治（shadow root 保存）

A/B 实测结论：

| 保存方式 | 页面能监听到这次点击吗 | 结果 |
|---|---|---|
| `<a>` 挂进 document 再派发 click | 能（document 捕获阶段计数 = 1） | 下载成功，但 B站 把它当「打开图片」→ **多弹一个标签页** |
| `<a>` 放进 closed shadow root + `composed:false` | 不能（计数 = 0） | 文件正常保存，**不弹标签页** |

所以 v1.2.18 起：shadow root 派发 → 游离节点 click → 挂进文档兜底（仅前两条都失败时）。评论区图片也改走同一套保存逻辑。

### 3.4.0.10 面板自己关掉？已加「自愈」（1.2.19 / 主版 1.7.9）

现象：点一下面板里的按钮，小窗就没了。原因不在脚本的关闭逻辑（只有 × 会关），而是外部把面板关掉或整块移除（B站 的全局点击监听 / SPA 重渲染 / 别的脚本）。

现在面板会**自愈**：你主动打开后，每 700ms 检查一次，被关掉或被移除都会自动恢复；你点 × 或再点右下角圆点时才算真的关闭。

### 3.4.0.11 圆点「点一下又自己关上」已修（1.2.20 / 主版 1.7.10）

真因：一次真实点击同时触发了 `mousedown` 捕获兜底和 `click` 两个开关，等于「开→关」。现在两个入口共用去抖的 `toggleSaPanel()`（400ms 内只认一次），点一下就是开，再点一下才是关。

### 3.4.0.12 为什么登录了还是 720P

1. **独立版油猴**：浏览器里只能拿渐进式 MP4（B站 这种地址上限 720P）。1080P60 只有 DASH 分离流，需要 ffmpeg 合并，浏览器做不到。v1.2.21 起会自动改下「视频轨 + 音频轨」两个文件（`-v.mp4` / `-a.m4a`，清晰度是真的 1080P60），要单文件请用 EXE / Docker / APK。
2. **主版油猴 → 服务端**：浏览器登录**不等于**服务端登录，服务端匿名时最高 720P。v1.7.11 起面板顶部直接显示「服务端：已登录 / 未登录（只能 720P）」，要高清就去 WebUI「账号登录」扫码或粘 Cookie。

### 3.7.1 多种文件类型可以同时勾选（v2.1.1 / 独立版 1.2.22）

`纯音频`、`无声视频`、`SRT 字幕`、`SRT 弹幕`、`封面`、`NFO` **想勾几个就勾几个**，勾中的全都下，文件名按类型加后缀互不覆盖：

- 纯音频 → `<名>.m4a`；无声视频 → `<名>-mute.mp4`；两个都勾就两个文件都要；
- 字幕 → `<名>.srt`；弹幕 → `<名>-danmaku.srt`；封面 → `<名>.jpg`；NFO → `<名>.nfo`；
- 附加文件只在视频下完后写一份，不会因为勾了两个主文件类型就重复。

### 3.4.0.13 推送版圆点在右上、改蓝色（1.7.13）

两个脚本同时装时，圆点不再叠在一起：推送版圆点上移到右下 132px 处并改成蓝色渐变，独立版仍在最底下；「N 张图」气泡也做了去重，只显示一个。

### 3.4.0.14 评论区图片「9 张只显示 8 张」已修（1.2.24 / 主版 1.7.14）

原因：只认 `img[src]` 与 `source[srcset]`，漏掉了**懒加载**（`data-src`）和**背景图**（`background-image:url(...)`）两种渲染方式，`srcset` 多候选时也只取第一个（小图）。现在会把 `src/data-src/data-original/data-fail-src/srcset/data-srcset/href/poster` 与 `background-image` 全扫一遍，`srcset` 取最高清那份，一张不漏。

### 3.4.0.15 评论九宫格「+1」里的图也能下（1.2.25 / 主版 1.7.15）

九宫格塞不下时会折进 `+1` 遮罩，那张图 DOM 里没有，只能从评论接口的 `content.pictures[]` 拿。现在挂按钮和点下载都以「接口列表 ∪ DOM 列表」为准，数量会自动从 8 校正成 9；同时处理了 `rpid` 超过 2^53 被 JSON 掉精度的问题（用图片 URL 反查兜底）。

### 3.9 失败重试与「连续下载不触发风控」

- 任务队列页新增「**重试失败**」：把 `error` 任务重新排队（保留原任务参数，进度归零），手机版在任务页同样有，失败行上还单独有「重试」。
- 「**取消全部**」不是只把状态改成 canceled，而是**直接从任务队列里删掉**所有任务（排队中 + 正在下载的都算）；
  正在下载的会先中止，再删除条目，任务页不会留下 canceled 占位。Docker/EXE、手机版、独立版油猴 v1.2.39 起行为一致。
- 「**清除已完成**」只清 `done/skipped/canceled`，**失败任务永远保留**，随时可以重试。
- 图文连下防风控：图文任务间隔 ≥2.6s + 随机抖动，每连续 8 个强制休息 25~45 秒（服务端与手机版都生效）；触发风控时整个队列自动暂停 2 分钟再继续。

### 3.4.0.16 多选发送后按钮不再卡在「解析中/发送中」

推送版 `finally` 里恢复了按钮文案并加了 12s 兜底；独立版改成点发送后立刻恢复按钮、把「加入队列」放后台执行，选完一批可以马上接着选下一批。

### 3.4.0.17 图片数气泡按地址去重（修 10 张显示成 20 张）

B站 图文页会把同一张图渲染两遍（SSR + hydration），旧实现数节点导致数字翻倍；现在按图片地址去重后再计数。

### 3.4.0.18 图文（opus）图片提取修复（独立版 1.2.44）

新版图文（如 `https://www.bilibili.com/opus/1262380051833290755`）把九宫格放在
`MODULE_TYPE_TOP.module_top.display.album.pics`，正文 `MODULE_TYPE_CONTENT` 里只有文字。旧 `opusPics()` 只扫正文，
于是点击下载会报「图文里没有找到图片」。

现在会同时扫描 **TOP 相册**和 **CONTENT 段落**，并把 `http://` 升成 `https://`、剥掉 `@720w...` 缩略参数、按 URL 去重，
最后用 `basic.image` 兜底。实测该动态 6 张图全部识别；旧版正文式图文不受影响。

### 3.4.0.19 图文右下角「6 张图」只显示 3 张已修（1.7.28 / 1.2.45）

`/opus/1262380051833290755` 有 6 张相册图，但旧版右下角显示 3 张。原因是计数只扫了 `.opus-module-content img`，
这里恰好是正文里的 3 个 `/bfs/emote/` 文字表情；真正的 6 张在 `.horizontal-scroll-album`（接口
`MODULE_TYPE_TOP.module_top.display.album.pics`）里，完全没被选中。

现在 DOM 计数会选 `.opus-module-top img` / `.horizontal-scroll-album img`，按 base URL 去重，并排除
`/bfs/emote|face|garb|pendant|banner|small_dynamic_cover/`；接口兜底也会数 TOP 相册。该页实测从 **3 修正为 6**。

### 3.10 刷新页面不丢进度（底部悬浮进度条）

WebUI 会全局轮询任务状态，并在底部显示 `正在下载 N 个 · 72%` 的悬浮条——**F5 刷新后仍然显示**，点「查看」进任务队列，点「×」只收起提示。

### 3.11 连不上服务器 / 下载失败怎么查

1. 「下载设置 → 网络自检」点「运行网络诊断」：会测 B站 主接口、Passport、视频 CDN，并检查两个下载目录是否可写。
2. 命令行同样可用：`curl -s http://NAS_IP:2196/api/diagnose | python3 -m json.tool`。
3. 推送版油猴现在 `@connect` 已放行 `192.168.*` / `10.*` / `172.*` / `*`，填 `http://192.168.x.x:2196` 这类局域网地址可以直接用；仍连不上时面板会直接列出排查项。

### 3.12 已知回归已修复（2.1.5）

2.1.1 引入「同时下纯音频/无声视频」时，`referer` 与 `dest` 的赋值被误挪进分支，导致普通视频下载报 `cannot access local variable 'referer'`。2.1.5 已修复，并顺手修好了「重复下载会生成 `-1` 副本」的问题（现在判定 `base` 存在即跳过）。

### 3.13 文集（readlist）与视频合集变量

- 文集：把 `https://www.bilibili.com/read/readlist/rl1100717` 贴进「链接下载」，会列出文集里的文章，可全选或单篇勾选，再点「下载选中文集文章」。文集接口要求**登录**，未登录会提示「需要登录：账号未登录」。
- 文集重命名规则（设置页新增一块）默认 `<readlist_title>/<readlist_order>-<opus_title>/<opus_id>-<opus_order>.<ext>`，即「文集标题/文章序号-文章标题/文章id-图片序号.jpg」。
- 视频重命名新增 `<videolist_title>`、`<videolist_order>`、`<videolist_id>`、`<video_author_uid>`；视频不在合集里时前三个自动忽略（变量连同相邻分隔符一起消失）。
- 视频合集链接 `https://space.bilibili.com/601598/lists/6413356` 也可以直接贴进来解析，会列出合集内全部视频并可勾选下载。
- 推送版油猴在文集页多选时会把 `readlist` 上下文一起发给服务端，因此服务端会按「文集重命名规则」落盘。

### 3.14 失败任务重试

任务队列里失败的任务行右侧有「重试」；页面顶部还有「重试失败」批量重试。手机版任务页同样有；独立版油猴脚本的队列区有「重试失败」，会把失败的文件重新排队。接口：`POST /api/tasks/retry`，body 传 `{"id": "任务id"}` 只重试一条，留空重试全部。

### 3.15 合集与分集缩略图

- **合集链接**（`/lists/<id>`）：解析后是一张缩略图网格，每个视频一张 `16:10` 封面 + 标题，点封面即选中，支持「全选 / 清空」；688 个视频也能流畅滚动（懒加载）。
- **合集 episodes / 多分集视频**：每个分集 pill 前面带一张 `44×26` 小封面，一眼能认出是哪一集。
- 单分集视频不显示分集缩略图（首帧经常是黑帧），视频卡片本身有大封面。
- 接口给的 `http://` 封面统一升级为 `https://`；图片挂了会自动回落视频封面，不会留黑块。

## 6. 防风控设计（重点）

B站风控主要看 **频率**、**指纹**（`w_webid`/`ExClimbWuzhi`）与 **接口选择**。本项目不去伪造指纹（伪造反而更容易被判），而是从「少发请求、发对的请求」入手：

1. **接口选择避开高危端点**
   - UP 主视频列表：**不再请求** `x/space/wbi/arc/search`（本机 IP 实测 412 / -352，硬刚必进小黑屋），改用 App 端 `app.bilibili.com/x/v2/space/archive`（`pn` 翻页、`order=pubdate`），单个 UP 主 57 个视频 3 页拿全；
   - UP 主图文列表：`x/polymer/web-dynamic/v1/opus/feed/space`（`offset` 翻页，无需 WBI）；
   - 视频信息一次 `x/web-interface/view` 同时拿 `pages` 与 `ugc_season`，不额外请求；
   - 未登录时**不发** wbi 版 playurl（必然 -101），只发一次普通 playurl；
   - 单 P 视频不再额外查 cid（直接用 `pages[0].cid`）。
2. **所有请求统一限速**：`api_interval`（默认 1.2s，最小 0.5s）在会话层串行排队，检索另有 `scan_interval`（默认 1.6s/页），下载任务间 `file_interval`（默认 0.8s/文件）+ 随机抖动。
3. **并发克制**：默认 `concurrency=2`（上限 4），且同一时刻只有 1 个请求真正在飞。
4. **风控码自动退避**：遇到 `-352 / -412 / 429 / 412` 等，按 20s → 45s → 90s 指数退避；**连续 3 次**风控则**自动暂停整个队列**，界面顶部与任务页显示冷却倒计时，冷却结束再逐步恢复。
5. **断点续传**：大文件写 `.part` + Range 续传，重试不会重复下载整段。
6. **失败不刷屏**：任务失败会记录原因（`-404` 稿件不可见、`-10403` 地区限制、无图等），不会无限重试。

7. **定时追更的额外克制**：同一时刻只有一个订阅在扫描（串行）、两个订阅扫描之间至少隔 `min_gap`（默认 90s，手动检查也算）、单轮最多建 `max_new` 个任务（默认 20，其余下一轮）、
   下载侧一旦冷却或扫描命中风控就整体让路；订阅扫描不会并发、不会补起点之前的历史（起点本身会下；不设起点时首次扫描只建基线）。

> 建议：批量任务在**深夜**跑；`api_interval` 不要低于 1.0s；UP 主作品数很多时把「扫描间隔」调到 2s 以上；同一 IP 不要同时跑多个实例；
> 定时追更的间隔**不要低于 30 分钟**（最小可到 2 分钟，但没必要）。

## 8. 常见问题

**Q：为什么默认只下到 720P？**
A：B站对**未登录**用户只给 720P（progressive）。登录后（扫码或 Cookie）即可拿 1080P60 / 1080P+ / 4K，DASH 音视频由 ffmpeg 无损合并。`BiliDL.exe` 需要旁边有 `ffmpeg.exe`；Docker 镜像里已内置 ffmpeg。

**Q：Cookie 怎么拿？**
A：浏览器登录 B站 → F12 → Network → 任意 `api.bilibili.com` 请求 → Request Headers 里复制整段 `Cookie`，粘到「账号登录 → 手动输入 Cookie」。至少需要 `SESSDATA`、`bili_jct`、`DedeUserID`。

**Q：扫码一直「等待扫码」？**
A：二维码 3 分钟过期，点「刷新」重新生成；手机 App 需登录同一账号并确认授权。

**Q：下载目录填了没生效？**
A：相对路径会落到服务的工作目录；建议填绝对路径。Docker 里只能写容器内可见的路径（`/download` 及其子目录），宿主其它目录需要额外挂载。

**Q：合集里为什么默认没勾？**
A：按需求「合集内其它视频默认不全选」。想整季下载点「全选合集」。

**Q：APK 连不上？**
A：确认手机与电脑同网段、电脑防火墙放行 2196、地址形如 `http://192.168.1.100:2196`；不要填 `localhost`（那指的是手机自己）。

**Q：会不会触犯 B站条款？**
A：请只下载你有权保存的内容（自己的作品、授权内容、离线观看），不要用于二次分发或商业用途。项目内置的低频与退避策略是为了「不给服务器添麻烦」，不代表可以无限量抓取。
